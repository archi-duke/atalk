# Go 전환 검토 (2026-11-17)

## 결론

**Go 로 전환했다.** 같은 데이터 폴더 형식과 같은 HTTP API 를 그대로 유지한다.
TypeScript 구현은 `ts/` 에 참조용으로 남겨 두고, 두 구현이 같은 API 를 따르는지 확인하는 호환성 테스트에 쓴다.

## 검토 항목

| 항목 | TypeScript (v0.1) | Go (v0.2) | 판단 |
|---|---|---|---|
| 배포 | Node 22.18+ 와 npm 패키지 필요 | 실행 파일 하나 (`atalk.exe`, 약 14MB). 데몬·CLI·MCP·훅·브리지 포함 | Go 유리. 훅과 브리지가 에이전트 PC 마다 깔려야 하므로 중요 |
| 훅 실행 속도 | 훅마다 Node 기동 + PID 찾기에 PowerShell 실행 (수백 ms~1초) | 바로 실행, PID 찾기는 Windows Toolhelp API 직접 호출 | Go 유리. SessionStart/Stop 훅은 매 턴 실행됨 |
| 프로세스 생존 확인 | `process.kill(pid, 0)` | `OpenProcess` + `GetExitCodeProcess` | Go 가 더 정확 (Windows 는 끝난 프로세스도 핸들이 남아 있으면 열림) |
| 동시 처리 | Node 단일 스레드라 순서가 저절로 보장됨 | 코어 전체를 mutex 하나로 직렬화 | 같은 보장. 이벤트 구독자는 버퍼 채널 + 느리면 버림으로 잠금 안에서 막히지 않게 함 |
| MCP SDK | 공식 TS SDK 1.32 | 공식 Go SDK v1.8.0 (안정판) | 동등. Go SDK 는 슬라이스/포인터를 `["null","array"]` 로 만들어서 단일 타입으로 정리함 |
| 상주 브리지 | 가능 | SSE 수신 + 외부 프로세스 실행이 표준 라이브러리로 충분 | Go 유리 |
| 이식 비용 | — | 코어 약 900줄, 전체 약 2,800줄 | 파일 형식/API 를 문서로 고정해 둔 덕에 1:1 이식 |

## 호환성 확인

- Go 코어 테스트 12개: TS 코어 테스트와 같은 시나리오 + **TS 가 만든 데이터 폴더를 Go 가 읽고 이어 쓰기**.
- **TS 의 HTTP 테스트를 Go 데몬에 그대로 실행**해 통과 (`ATALK_TEST_URL=... node --test ts/test/server.test.ts`).
- Go MCP 서버를 TS MCP 클라이언트로 호출해 18개 도구 동작 확인.

## 남은 위험

- Windows 에서 실행 중인 `atalk.exe` 는 덮어쓸 수 없다. 업데이트할 때 데몬/브리지를 먼저 멈춰야 한다.
- 메시지 파일을 매번 처음부터 읽는 구조는 그대로다 (방 메시지 한도 1000 으로 막아 둠).
